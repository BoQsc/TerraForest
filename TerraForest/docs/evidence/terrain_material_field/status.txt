2026-10-13: TERRAIN-AWARE DIRECT MATERIAL EDITS
TerrainCore.material_box now stages bounded box CSG changes to the existing
material density pages, intersecting them with the complement of a second
TerrainCore solid field. Both owners are locked together and the expected
solid revision is checked before editing. This introduces no new mesher.
Invalid/stale requests leave the field unchanged. Allocation is preflighted;
new empty pages are rolled back if allocation fails before density publication.
Existing geometry cache and archive paths remain authoritative.

Release check now passes 26 assertions (terrain_exclusion.log), including
sample exclusion, direct removal, stale/invalid rejection, and identical mesh
on archive reload. Both debug and release DLLs rebuilt with the prebuilt SDK.
This does not prove rendered shoreline contact, physical volume conservation,
sub-grid visibility, flow, or live lake integration. The operation currently
accepts boxes up to 32 metres per axis; large fills need bounded scheduling.
The live water runtime is still unchanged. No playtest acceptance claimed.

2026-10-13: EXISTING TERRAIN WORKER INTEGRATION
The public terrain facade now accepts a bounded material_edit request. It uses
the existing persistent terrain worker, preserves mutation/save ordering, and
limits admission to one request including unconsumed completion. Inputs are
copied and validated. Native code checks both material and solid revisions
under the same paired lock. Reset/cancellation epochs reject queued stale work.
The result identifies its world epoch rather than hiding an old-world commit.

2026-10-13: BUCKET-SCALE GEOMETRY GATE FAILS; NATIVE MEASUREMENT ADDED
The new direct material field must not equate analytic brush dimensions with
transferred volume. tests/terrain_material_volume.gd measures actual runtime
triangles: an integer-aligned 1m box has no surface, a half-grid-offset 1m box
renders 0.037m3; 2m and 4m boxes also shrink. All six target-volume cases fail.
This is the existing one-metre lattice plus surface representative averaging,
not a bucket inventory defect. No runtime migration is accepted on that basis.
Raw failures are retained in bucket_scale_failures.{json,log}.

Native measure_material_surface now integrates the same full-detail extraction
and connectivity, without lighting, GPU upload or a separate water mesher.
Requests are limited to 32m per axis. It checks oriented edge closure and
returns physical volume only for a closed envelope (including empty zero).
Open patch integrals are explicitly named signed_integral_m3, not volume.
This enables bounded before/after accounting; it does not yet implement a
volume-constrained transfer or prove adequate runtime latency.

The 31-check native suite passes including independent render-triangle
agreement, open-patch rejection and bounds. Bucket-scale failures remain open;
never treat the passing measurement tests as acceptance of the measured shape.

2026-10-13: REJECTED ITERATIVE BRUSH-VOLUME SOLVER
A bounded 16-step radius search was implemented and measured before runtime
integration. It failed all four one-cubic-metre grid-offset cases. The best
under-capacity samples were 0.2963, 0.125, 0 and 0.125m3; intermediate mesh
volumes were skipped at topology changes. Requests were rolled back correctly,
but that does not make the solver a viable interaction implementation.
Trial duration was about 5-6ms here, not a general performance guarantee.

The failed native implementation and public binding were removed, and installed
terrain DLLs restored to the committed version. Failed test source and output
remain as evidence only. Do not add iterative fitting or per-click search to
live bucket gameplay. The unresolved issue is small-volume representation by
the existing shared density extraction; direct reference-project interaction
remains the target. Static water scope continues: no flow or spillage.
