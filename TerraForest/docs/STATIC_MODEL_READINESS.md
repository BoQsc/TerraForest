# Static-model collision readiness

`NativeStaticBatch.is_collision_region_ready(world_bounds)` extends the existing block walking gate to placed model floors, walls and compound proxies. `NativeStructureQueries` combines block and model checks; the world controller supplies its conservative capsule/floor-snap/travel bounds before moving. A false result holds movement with zero velocity and retries using current input next tick. Editor flight still bypasses walking collision gates.

The native query rejects malformed bounds and invalid collection transforms. It visits existing cached spatial-group proxy bounds, then only overlapping placements and their individual configured boxes. It does not allocate physics objects or enumerate a caller-sized world grid. Authored overlapping proxies require an admitted body for the collection's current transform. Disabled collision, pending admission, capacity deferral and transform changes cannot claim readiness merely because a pending queue is empty. Unrelated distant missing bodies do not block local movement. Collections without proxy metadata remain intentionally decorative.

Individual compound boxes preserve doorway openings; transformed boxes use conservative enclosing AABBs, so rotated geometry can hold movement somewhat before exact contact. This is a safety query, not a replacement for physics narrow-phase collision. The existing index caps at 4,096 origin groups per collection; dense overlapping groups can still require checking many records. It is not a hard-time-bound scheduler or an additional spatial tree. Global physics memory budgeting, vehicle sweeps, authoritative region paging and multiplayer remain unfinished.

Regression coverage adds model pending/resident/empty-region/invalid-bound/distant-body and immediate transform-change cases, plus compound openings and shape-budget deferral. The graphical world test exercises actual player waiting above an unavailable static floor, automatic resume/landing, loss of that floor's collider and removal releasing the gate. Run `tools/validate.py --test static_placements`, the equivalent clean release check, and `tools/validate.py --test structure_world --gpu` with the Godot executable supplied.

Validation on Godot 4.7.2: all 235 placement checks passed for both native debug and release builds; all 159 integrated world checks passed at 1920×1080 fullscreen. The first graphical run passed the new movement cases but rejected synthetic sphere edits after losing focus. That fixture now explicitly sets its intended focus state immediately before each simulated edit; the full rerun passed. Retained reports and build fingerprints are in `docs/evidence/static_model_readiness`. Neither these correctness checks nor simultaneous development builds establish frame-time or endurance guarantees. Both extensions linked the pinned prebuilt SDK with Zig 0.16; no godot-cpp source files were compiled.
